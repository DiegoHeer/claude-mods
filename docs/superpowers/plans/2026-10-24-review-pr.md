# review-pr skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/review-pr` skill that runs review → post → triage → fix → push → reply on a PR from the session that wrote it, with one stop for triage approval.

**Architecture:** A new Markdown skill orchestrates two existing skills. A fresh subagent runs `code-review` then `post-review-comments` on the PR. The main session then follows `handle-pr-comments`, given a new `--auto-push` argument that skips its pre-commit stop.

**Tech Stack:** Claude Code skills (Markdown `SKILL.md` with YAML frontmatter), `gh` CLI. No code, no unit tests: verification is a live run on a throwaway PR.

**Spec:** `docs/superpowers/specs/2026-10-24-review-pr-design.md`

## Global Constraints

- Skills live in `skills/library/<name>/SKILL.md`, installed by `/skills:install`. Write in the style of the existing library skills (short imperative steps, `bash` blocks for exact commands).
- `handle-pr-comments` without `--auto-push` behaves exactly as today. `post-review-comments` changes only in how it locates `build_review.py` (Task 1b).
- Location-agnostic: refer to other skills by name only, never by path. Check they exist from the session's available-skills list, which covers global (`~/.claude/skills/`), repo (`.claude/skills/`) and plugin installs alike.
- The reviewer subagent never gets the main session's context: dispatch it with the Agent tool, `subagent_type: "general-purpose"`, never `"fork"`.
- One round only. No re-review of fix commits. No CI watching in the skill.
- The one stop is triage approval. Nothing is committed or pushed before it.
- Commits follow Conventional Commits. Do not commit until Diego has reviewed the branch (global rule; it applies to building this skill, not to the skill's own runtime behaviour).

## Review Focus

1. Current branch has no PR and no number is passed → stop with "no PR found, pass a PR number"; no subagent dispatched. Checked in Task 3, case B.
2. PR number passed while on another branch → `handle-pr-comments` must not commit fixes onto the wrong branch; `/review-pr` stops if the current branch is not the PR's head branch. Checked in Task 3, case C.
3. Subagent finds nothing and PR has no other unresolved root comments → "PR is clean", no triage, no commit. Checked in Task 3, case D.
4. Working tree has uncommitted changes when `/review-pr` starts → stop and ask to commit or stash first, so the auto commit (`git add -A`) does not sweep them in. Checked in Task 3, case E.
5. Posting fails (422 or auth) → stop, show the error, no triage. Covered by step wording in Task 2 (not live-tested: hard to force).

**Interfaces:**

- [ ] **Step 1: Write `skills/library/review-pr/SKILL.md`**

Frontmatter: `name: review-pr`, `argument-hint: "[PR number] [effort level]"`, `user-invocable: true`, and a `description` that triggers on "review my PR", "review and handle the PR", "/review-pr". Body, as numbered steps:

1. Preflight, in this order, all before any change:
   - Needed skills: `handle-pr-comments` and `post-review-comments` must be in the available skills (by name; `code-review` is built in). If one is missing, stop and propose: run `/skills:install` and pick the missing ones, then `/reload-plugins` or a new session. If `/skills:install` is not available either, first give `/plugin marketplace add DiegoHeer/claude-mods` and `/plugin install skills@claude-mods`. Do not install anything yourself.
   - `gh auth status`. Find the PR (`gh pr view [N] --json number,headRefName,url`). Stop if none. Stop if `git branch --show-current` is not the PR's `headRefName`. Stop if `git status --porcelain` is not empty.
2. Dispatch one reviewer subagent (Agent tool, `general-purpose`). Its prompt names the PR number and owner/repo, says it has a clean context on purpose, tells it to run the `code-review` skill on that PR (pass the effort level if given), then the `post-review-comments` skill on the findings, to change no files, and to reply with the review URL and the inline / summary / skipped counts — or the error if posting failed.
3. If the subagent reports an error, stop and show it.
4. Follow the `handle-pr-comments` skill with `<PR number> --auto-push`. If it finds no root comments to triage, report "PR #N is clean" and stop.
5. Final summary: the review URL, then the `handle-pr-comments` summary.

One line near the top: this flow commits and pushes without a second pause on purpose; the triage approval is the sign-off.
